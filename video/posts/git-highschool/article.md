何も知らずにGitHubを使ってませんか。
知らずに使うと、壊れます。
GitHubの緑のボタンは、3つだけ。
押す前に見る場所は、1つしかありません。
この記事では、GitHubの画面で見る場所と押す場所を、赤枠で全部示します。
つないで、提出させて、差分を見て、合わせて、戻す。
この1周を、実際の画面10枚で回します。

## 第1章：GitHubにつなぐ｜リポジトリを作って、手元の記録を上げる
GitHubの画面は、英語です。
でも、押す場所は決まっています。
画面の赤枠が、見る場所と押す場所です。
この章で押す緑のボタンは、1つだけです。
まず、リポジトリを1つ作ります。
リポジトリは、Gitの記録をネットに預けるロッカーのことです。
ロッカーの中身と、4つの言葉は、前作で書きました。

読んでいなくても、この記事だけで1周は回せます。
GitHubにログインして、右上の「+」から「New repository」を選びます。
https://github.com/new を開いても、同じ画面です。
入れるのは、名前だけです。
「Repository name」に、英数字で名前を入れます。
「git-practice」で構いません。
「Choose visibility」で「Private」を選びます。
非公開、という意味です。
「Add README」のスイッチは、今回はオフのままにします。
手元にもう記録があるときは、空のまま作るほうがつなぐのが簡単だからです。
いちばん下の緑の「Create repository」を押します。
押した直後の画面が、この章でいちばん大事です。
下のほうに、「…or push an existing repository from the command line」という見出しがあります。
その下の3行が、今日使う命令です。
上の7行は、手元にまだ記録がない人向けなので、飛ばして構いません。
3行の意味は、こうです。
1行目：手元の記録に、このロッカーの住所を教える。
2行目：本流の名前を「main」にそろえる。
3行目：本流をロッカーに預ける。
この画面の住所（赤枠）をコピーして、AIに1行送ります。
Claude Codeは、3行を自分で打ちます。
Claude Codeは、指示を受けてパソコンの中で作業してくれるAIです。
僕の指示書では、pushの前に確認を取る決まりにしています。
pushは、手元の記録をロッカーに預ける操作です。
だから、ここで一度止まります。
「はい」と答えたら、ブラウザの画面を更新してください。
さっきまで3行の命令だった場所に、手元のファイルが並びます。横に、コミットの文が出ます。
これが「つながった」の合図です。
ここで1つ、見てほしい場所があります。
ファイルの一覧の上にある「main」という文字です。
今、ロッカーの中で見ているのが、どのしおりかを示しています。
しおりは、ブランチのことです。
いま、どの列に記録を積んでいるかの目印です。
この「main」は、これから先、直接は触りません。
僕も最初は、ここをよく見ていませんでした。
mainの上で作業して、戻る場所を探すのに時間を使いました。
つながらないときは、たいてい住所です。
末尾の「.git」が落ちている。
アカウント名の綴りが違う。
「not found」と出たら、画像②の住所をもう一度コピーしてください。
ここまでで、手元の記録がGitHubにつながりました。次は、プルリクエストで合わせる、毎日の1周です。

## 第2章：プルリクエストで合わせる｜AIの作業を提出させて、差分を見てから押す
ここからが、毎日の1周です。
プルリクエストは、「合わせてください」と出す提出のことです。
この章で押す緑のボタンは、3つです。
手を動かすのは、AIです。
自分がやるのは、見ることと、押すことだけです。
まず、AIに1行送ります。
READMEは、リポジトリの説明を書く、最初のファイルです。
Claude Codeは、ブランチを作ります。
ファイルを書き換えて、コミットします。
最後に、pushの手前で止まって聞いてきます。
「はい」と答えたら、ブラウザでロッカーを開きます。
上に、黄色い帯が出ています。
「さっき、このブランチに預けたよ」という知らせです。
右の緑のボタン「Compare & pull request」を押します。
これが『提出』です。
下書きのノートを、先生の机に出す。
出しただけでは、清書には1文字も写っていません。
清書に写すのは、見たあとです。
提出の画面で見る場所は、3つです。

## 1つ目は、いちばん上の矢印です。
「base: main」と「compare: 作業ブランチ」
どこへ、どこから合わせるかです。
左がmainになっているかだけ、確かめます。

## 2つ目は、「Add a title」の題名です。
AIに作らせると、変更の要約が入ります。
自分で出すと、最初からコミットの文が入っています。
自分で出すなら、1行で「何をしたか」を書きます。

## 3つ目は、緑の「Create pull request」です。
押すと、提出が受け付けられます。
提出のあとに、人の出番があります。
画面の上に、タブが4つ並びます。
見るのは、右端の「Files changed」だけです。
変わったファイル、という意味です。
緑の行が、足された行です。
赤の行が、消えた行です。
これが、差分です。
頼んだ3行が緑なら、合格です。
画面の例では、見出しと空行を足したぶんも緑なので、6行です。
頼んでいない赤があったら、合わせません。
画面の例では、赤が1行あります。
「置いてあるもの」から、メモの1行が消えています。
頼んだ覚えがなければ、ここで止めます。
AIに「この赤い行は、何で消したの」と聞きます。
ここが、AIに任せる作業で、いちばん大事な30秒です。
レビューの通知を見るだけで胃が重くなっていた頃の僕は、ここを見ずに押していました。
今は、赤い行の数だけ、先に数えます。
頼んだ覚えのない赤が1本でもあれば、止めます。
差分に問題がなければ、「Conversation」に戻ります。
下のほうに、緑の「Merge pull request」があります。
その上に「No conflicts with base branch」と出ていれば、そのまま合わせられます。
押すと、「Confirm merge」に変わります。
もう一度押します。
これで、作業ブランチの記録が、mainに合わさりました。
色が紫に変わって、「Merged」と出ます。
下に「Pull request successfully merged and closed」の箱が出ます。
その右に「Delete branch」があります。
押して構いません。
消えるのは、ロッカーの中の作業ブランチの「しおり」だけです。
記録はもうmainに合わさっているので、何も失いません。
最後に、手元を最新にします。
AIに「mainに切り替えて、GitHubの最新を取り込んで」と送ります。
これで1周です。
次の作業は、また新しいブランチから始めます。
mainの上では、作業しません。
ここまでで、提出して、差分を見て、合わせる1周が回りました。次は、合わせたあとで間違いに気づいたときに押す、Revertの話です。

## 第3章：Revertで戻す｜合わせたあとでも、ボタン1つで打ち消す
合わせたあとで、間違いに気づくことがあります。
Gitでは、預けた記録を消さずに「打ち消し」ます。
GitHubの画面には、そのためのボタンがあります。
それが「Revert」です。
さっき合わせたプルリクエストを、もう一度開きます。
「merged commit … into main」と書かれた行があります。
その右端に、「Revert」があります。
押すと、何が起きるか。
記録は消えません。
反対の変更を入れた、新しいプルリクエストが作られます。
公式の説明でも、合わさるのは、その新しいプルリクエストを合わせたときです。
だから、戻すときも、第2章と同じ1周を回します。
差分を見て、緑のボタンを押す。
消したのではなく、「戻した」という記録が1つ増えます。
AIに頼むなら「さっき合わせたプルリクエストを打ち消して」です。
Claude Codeは、git revert で同じことをします。
もう1つだけ、出会う画面があります。
「This branch has conflicts that must be resolved」。
衝突です。
mainと作業ブランチで、同じ行を別の形に直したときに出ます。
緑のボタンは灰色になって、押せません。
ここは画面で直さず、AIに1行送ります。
どちらを残すかだけ、自分で決めます。
AIが直してもう一度預けると、緑のボタンに戻ります。
衝突は、失敗ではありません。
同じ行を2回直した、という事実が表に出ただけです。
最後に、画面に出ないものを1つだけ。
鍵です。
パスワードやAPIの鍵が入ったファイルは、GitHubに上げてはいけません。
Revertで戻しても、一度上がった鍵は見られたものとして、作り直しです。
上げる前に、AIに「.envを記録から外して」と1行送ります。
僕の現場でも、AWSの設定を文字のファイルで書いて、同じ1周で回しています。
差分を見ずに合わせた設定は、そのまま本番で動きます。
だから、押す前の30秒を、AIには渡していません。
画面のボタンは、全部、人が押す。
AIに任せる範囲を広げても、ここだけは変えていません。
ここまでで、つないで、提出して、合わせて、戻す1周がそろいました。
