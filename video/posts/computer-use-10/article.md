画面越しに CapCut を動かすまで
44.4秒のリール1本に、字幕が26個、差し込みの画像が15枚。CapCut で手で並べると、同じクリックの繰り返しですよね。
実は、Claude Code には2026年3月から、Computer Use という機能が入っています。公式の日本語版では「コンピュータ使用」と呼ばれ、Claude が画面を見て、クリックして、文字を入力する仕組みなんです。
今までは、ここが壁でした。API（アプリを外から動かす窓口）や公式の連携が無いアプリは、AI から動かせなかったんです。でも今は違います。Claude Code の Computer Use なら、CapCut や Keynote も画面越しに動かせます。
動き方はシンプルです。Claude が画面の写真を撮り、ボタンの位置を見つけて押し、もう一度写真を撮って結果を確かめます。触るアプリごとに許可が要り、私が許可したアプリだけが動きます。2026年3月23日に研究プレビュー（試験公開）として始まり、9月2日からは裏で動く形にも対応しました。
実際に私は、このPCの Claude Code に「次だけCapCut立ち上げてやってみて」と頼みました。すると Claude Code が CapCut を開き、新しいプロジェクトを作ったんです。44.4秒のリールの書き出しまで、そのまま進めています。
画像と字幕の並びは、Claude Code が CapCut の保存ファイルに書き込み、画面で開いて確かめていました。字幕の書体も、一覧の検索欄に「丸」と打って「源泉丸ゴシック-Bd」を選んでいたんです。
途中で1度だけ、Claude Code では押せない窓が出て、私が「キャンセル」を押しました。操作は裏で進むので、同じ Mac で私はほかのアプリを使えます。記事のための収録でも、私は途中から席に戻ってPCを使っていました。仕上がった5本のリールも、あとで約11分で続けて書き出しています。
あなたが毎週、同じ手順で触っているアプリはいくつありますか。CapCut、Keynote、Numbers、音の編集ソフト、自分で作ったアプリ。連携が無いから手でやるしかないと思っていたアプリがあれば、それが最初の候補になります。
記事では、このPCで Claude Code に任せた5つと、海外と X で見つけた5つを紹介します。何ができるか、どう始めるか、どう頼むか、どこでつまずくかを、第1章から第4章で順に書きました。
第2章には、Grok Bot に X を調べさせた依頼文を載せました。第3章には、音楽プロデューサーが Logic Pro の書き出しを任せた例も入れています。第4章には、このPCで止まった場面もそのまま書きました。

## 3月23日の公開から、9月2日の「裏で動く」まで
第1章では、公開の流れと始め方を押さえます。実はこのPCでも、最初の起動は「別の Claude の会話がコンピューターを使っている」という表示で止まりました。同じ Mac の別の会話が、画面を使っていたんです。

## 公開の流れと、使える人は Pro・Max だけ
新しい機能は、いつから誰が使えるのかが一番分かりにくいですよね。記事ごとに書いてあることが違うと、自分の環境で動くのか迷います。
私は、このPCの Claude Code のデスクトップアプリから使っています。許可を出すと、Claude Code はアプリの窓を前に出さずに裏で操作しました。9月2日に公開された「裏で動く」形です。
公開からの半年で、使える場所は4段階で広がりました。具体的にどう広がったかというと、こうです（日付は世界標準時。日本時間ではどれも翌日）。
2026年3月23日：Cowork と Claude Code のデスクトップアプリで公開。最初は macOS だけ
2026年3月30日：ターミナルの Claude Code（CLI）でも使えるように
2026年4月2日：デスクトップアプリが Windows に対応
2026年8月20日：開発者向けの API でも一般提供に（Computer Use を組み込んだアプリを作る人向け）
2026年9月2日：裏で動く形に対応。macOS 15以降で、人のマウスとキーボードを奪わない
使えるのは Pro と Max のプランで、Team と Enterprise では使えません。今も研究プレビューの扱いで、ターミナル版は macOS だけ、-p を付けた実行では動きません。実践のコツは、ターミナルなら /status でプランを先に確かめることです。要するに、Mac と Pro 以上のプランがあれば今日から試せるということです。

## 始め方は /mcp か設定1つ。守られている3つの決まり
設定画面のどこを触ればいいか、探すだけで疲れますよね。記事のための収録では、Keynote や CapCut など7つのアプリを一度に申請し、7つとも「full」で許可されました。具体的にどう始めるかというと、こうです。
ターミナル：/mcp を開き、computer-use を選んで Enable
デスクトップアプリ：設定の Computer use（日本語表示は「コンピューターの使用」）をオン。公式 X の案内は「設定 ＞ 一般」、公式ドキュメントは「Settings > This computer > System」で、資料によって表記が違います。アプリの版で表示が違うことがあります
Mac：初回に、アクセシビリティと画面収録の許可を求められる
許可はアプリごとに「Allow for this session」か「Deny」を選び、その会話の間だけ続きます。段階は、ブラウザが見るだけ、ターミナルや IDE（プログラムを書くアプリ）がクリックだけ、残りはすべてです。Esc を押せばすぐ止まり、画面を使えるのは同時に1つの会話だけです。
ここがポイントなんです。道具の順番は、MCP（アプリと直接つなぐ部品）やコネクタが先です。次が Bash と Claude in Chrome で、Computer Use は最後になります。実践のコツは、Gmail や Slack のようにコネクタがあるアプリには、画面越しに頼まないことです。

## CapCut・Grok Bot・Keynote・Numbers で試した5つ
第2章は、このPCで Claude Code に頼んだ実際の作業です。うまくいった手順と、つまずいた所の両方を書きます。

## 1. CapCut の編集を、44.4秒のリールの書き出しまで任せる
字幕を1つずつ打ち、書体を1つずつ変える作業は重いですよね。本数が増えるほど、編集の時間も増えます。
私が頼んだのは「次だけCapCut立ち上げてやってみて」の一言でした。Claude Code は CapCut を開き、アップデートと有料プランの案内の窓を閉じました。続けて、空のプロジェクトを作っています。
実は、全部を画面で押したわけではないんです。具体的にどうやったかというと…
並べる：差し込みの画像15枚と字幕26個は、プロジェクトを閉じた状態で CapCut の保存ファイルに書き込んだ
付ける：書体「源泉丸ゴシック-Bd」と、冒頭の文字の「タイプライター」の動きを、画面で1つにだけ付けた
写す：CapCut が保存した設定を読み、残りの字幕と画像14枚に同じ設定を書き写した
直す：「ソフトズームイン」で影が黒く出たので「フェードイン」に替え、2回目を書き出した
押さない：Pro の印が付いた素材は選ばず、更新・購入・シェアのボタンも押していない
実践のコツは、素材をムービー（Movies）フォルダの下に置くことです。CapCut は決まった場所しか読めない設定で、ほかの場所の素材は「メディアをリンク」の窓になりました。「メディアをリンク」の窓は CapCut の許可では押せず、私が「キャンセル」を押しています。仕上がった5本は「どんどんやれ。」の一言で、同じ手順を繰り返して約11分で書き出しています。

## 2. CapCut を操作する画面を、Claude Code が自分で録画して差し込む
AI で作った動画を出すなら、本物の操作画面を見せたいですよね。でも自分で画面録画を回すと、カーソルや通知まで写り込みます。
私は「あなた自身で収録して」「動画の中に差し込んでください」と頼みました。Claude Code はまず、窓1つだけを録画する道具 winrec を Swift で書きました。Mac の ScreenCaptureKit という仕組みを使うので、カーソルとほかの窓は写りません。
録画を回しながら CapCut を操作すれば、操作がそのまま動画の素材になるんです。具体的にどうやったかというと…
録る：録画を裏で始め、置き場で画像を選ぶ、「フェードイン」を押す、「エクスポート」を押す、の場面を CapCut で操作した
切る：録った映像から使う場面を時刻で切り出し、差し込み用の6本にした
足す：カーソルが写らないので、押した所に白い輪を描いた
隠す：フォルダの場所（個人名を含む）が写る範囲をぼかした
札：完成した47.0秒のリールでは、「実際の CapCut の画面」という札を6か所に出した
実践のコツは、裏で動く CapCut の弱点を知っておくことです。裏で動かすとプレビューの絵が1秒に1回ほどしか変わらず、再生の場面はコマ送りに見えました。置き場からタイムラインへドラッグすると、タイムラインが別の窓に分かれたこともあります。私の見立てでは、録る場面はボタンを押す瞬間に絞るのが向いています。

## 3. Grok Bot で X リサーチを実行して、CM の素材にする
X のリサーチは、検索して、読んで、表にまとめるまでが長いですよね。私は「このPCにGrok Botあるから」「あなたがやって収録して」と頼みました。1回目の許可は拒否になりましたが、Claude Code は勝手に続けず、進め方を3つの選択肢で聞いてきました。2回目で許可を出すと、Grok Bot の入力欄に依頼文を入れて送信し、回答が出るまでを窓ごと録画したんです。
正直言うと、回答の表がそろった理由は依頼文にあると私は見ています。具体的にどうやったかというと、依頼文に5つの決まりを書きました。
期間：「2026年10月6日〜10月9日（日本時間）」
対象：OpenAI と Anthropic の公式アカウント4つの投稿だけ
出力の形：「日付｜アカウント｜発表の要点｜投稿URL」の表
分からないとき：該当がなければ「該当なし」、取れない項目は「確認できず」と書き、「推測で埋めないこと」
しないこと：投稿や返信などの書き込み
回答は14件の表で、4つのうち1つのアカウントは「該当なし」でした。続けて送った2件目では、直近24時間の日本語の反応を、称賛・不満・要望・質問・比較に分けさせています。録画した窓は、60秒の CM の主役にしています。
実践のコツは、回答を使う前に公式発表と照合することです。CM では、画面で囲んだ2行だけを公式発表と照らし合わせて使いました。もう1つ、裏からのスクロールはエラーになり、PageUp も効きませんでした。

## 4. Keynote で、記事のメモからスライドを3枚作る
スライドは、中身が決まっていても、枠に文字を入れていく作業が長いですよね。1枚ずつレイアウトを選び、タイトルと箇条書きを打つ手間は毎回同じです。
記事の告知用に、Claude Code に Keynote でスライドを3枚作ってもらいました。1枚目のタイトルは「Claude Code × Computer Use」、2枚目は「このPCで実際にやった5つ」、3枚目は「Computer Use の決まり」です。1枚目の日付の欄には「2026年10月　X記事の告知用」と入れました。最初はテーマの絵を1回クリックしても選ばれず、既定の「ダイナミッククラウド（ライト）」のまま作りました。
ここから、裏で効く押し方が見えてきたんです。具体的にどうやったかというと…
文字の枠：1回のクリックでは選ばれず、ダブルクリックで入力に入れた
新しいスライド：メニュー「スライド ＞ 新規スライド」は裏からだと「無効」。ツールバーの「スライドを追加」なら押せて、「タイトル&箇条書き」を選べた
入力：枠をダブルクリックで決めたあとは、その場所にそのまま打ち込む形で文字が入った
箇条書き：行の区切りは Return キーで入った
できなかったこと：背景を暗い色に変えるクリックは、裏からは効かなかった
実践のコツは、メニューで止まったらツールバーを試してもらうことです。依頼文に「メニューが無効なら、ツールバーの同じボタンを使って」と1行足しておく手があります。

## 5. Numbers で表を入れて、3D の縦棒グラフまで作る
表とグラフは、数字を打ち込み、範囲を選び、グラフの種類を探して…と手数が多いですよね。セルが1つずれるだけで、グラフの形も変わります。
Numbers では、このPCで Computer Use を使った作業ごとに、操作の回数を表にしてもらいました。中身は、CapCut の編集186、収録111、続きの編集44、5本の書き出し61、Grok Bot 41 です。起動直後はファイルの一覧が出る「開く」の窓が出たので、そこは映さず、メニューの「ファイル ＞ 新規…」から作っています。テンプレートの「空白」は、1回のクリックでは開かず、ダブルクリックで開けました。
入力は、マウスよりキーボードの方が確実でした。具体的にどうやったかというと…
入力：矢印キーで A1 のセルへ行き、文字を入れ、Tab で右のセル、Return で次の行へ。6行×2列を入れた
選ぶ：Shift＋矢印で表の範囲を選んだ
グラフ：メニュー「挿入 ＞ グラフ」は「無効」だったので、ツールバーの「グラフ」→「3D」→ 1つ目の縦棒で入れた
色：右の「グラフスタイル」の絵はダブルクリックで効き、橙と黄色の系統に変わった
題名：「タイトル」をオンにして、「Computer Use の操作回数（作業ごと）」と入れた
実践のコツは、表の入力をキーボードで頼むことです。依頼文に「セルの移動は Tab と Return で」と書いておくと、Claude Code はマウスで狙う必要がなくなります。

## 6. スクショ付きの操作マニュアルを作らせ、設定を一括で登録する
人に操作を教えるとき、画面を撮り、矢印を足し、手順を書く。マニュアルづくりは、思った以上に時間を取りますよね。ソフトの版が変わるたびに、撮り直しも出てきます。
2026年3月24日、国内の AI 発信者が X に投稿した例です。Cowork の Computer Use で、操作マニュアルを作らせています。反応は、いいねが1,149件、表示が約26.8万回です。同じ発信者は翌日、設定をまとめて登録させる使い方も試しています。
私の見立てでは、操作しながら写真を撮る Computer Use の動き方は、手順書づくりと相性がいいんです。具体的にどうやったかというと…
マニュアル（Cowork）：デスクトップアプリを操作させながら1操作ごとにスクショを保存させ、画像付きの説明書にまとめさせた。補足では、OBS の FPS 設定を変える手順書も同じ方法で作った
一括登録（Cowork）：音声入力アプリ Super Whisper に、YouTube台本用・翻訳用・記事作成用・箇条書き用の4つのモードを、プロンプトからモデル選び・言語設定まで一度に登録させた
実践のコツは、繰り返しの設定と手順書づくりに使うことです。同じ発信者はまとめの投稿で、向く場面を3つ挙げていました。放置できる定型作業、スクショ付きの資料づくり、何パターンもの繰り返し設定です。速度は遅いものの、Dispatch でスマホから頼めば寝ている間に終わる、という評価です。

## 7. Final Cut Pro・Premiere Pro・CapCut の「下ごしらえ」を任せる
動画編集で手間がかかるのは、プロジェクトを作り、素材を読み込む準備だったりしますよね。海外の個人クリエイターの YouTube（2026年3月24日）の例です。Cowork で Final Cut Pro を開き、新しいプロジェクトを作って動画を読み込みました。
私の見立てでは、動画編集ソフトはカットより準備の方が任せやすいんです。具体的にどうやったかというと…
Final Cut Pro（Cowork）：「7分16秒から最後まで、点滅する subscribe の文字」と頼むと、タイムコードで位置を合わせ、不透明度のキーフレームで点滅させた
Premiere Pro（Cowork、AI 教育チャンネルの YouTube、2026年4月1日）：「Claude demo」という新規プロジェクトを作り、動画の読み込みとタイムラインへの配置まで成功
Premiere Pro（デスクトップアプリの Claude Code、国内の X 投稿、2026年10月7日）：切り抜き動画の構成・カット・字幕まで作り、Premiere は Computer Use で操作したという報告
CapCut（Mac、国内の X 投稿、2026年4月2日。どのアプリからかは書かれていない）：起動 → 取り込み → トリミング → テキスト → 書き出しまで
実践のコツは、限界も先に知っておくことです。4月の Premiere Pro の例では、初回は約10分かかり、基本のカット編集はできなかったと報告されています。10月の報告ではカットまで進んでおり、報告によって結果が分かれています。

## 8. iZotope と Logic Pro、API のない音のソフトを画面ごと動かす
音の編集は、開いてフィルターをかけて保存、を何本も繰り返しますよね。海外の開発者講座の YouTube（2026年3月30日）の例です。ターミナルの Claude Code で、iZotope に WAV を3本処理させました。発信者は、API も CLI もないアプリだという点を挙げています。
途中でつまずいても、画面を見て立て直すところが面白いんです。具体的にどうやったかというと…
iZotope（ターミナルの Claude Code）：Movies フォルダの WAV を開き、フィルターのボタンをスクショで見つけて押し、Render。ダイアログを閉じるミスを2回したが、スクショで気づいて開き直した。最後に3本とも上書き保存
Logic Pro（Cowork、TV・映画向けの音楽プロデューサーの YouTube、2026年3月31日）：パート別の音源（ステム）を作る作業を、スキル「create stems」にまとめた
質問に答える：Claude が WAV か AIFF、44.1kHz か 48kHz、24bit か 16bit を聞いてくる。答えると、トラックをソロにしてステムごとに書き出し、デスクトップの stems フォルダに drums／orchestra／synth の WAV を保存した
実践のコツは、毎回同じ質問をスキル（手順書）にまとめておくことです。Logic Pro の例では、ソロのボタンを押しすぎたため、スキルに指示を書き足していました。

## 9. Unreal Engine の書き出しなど、MCP に無い操作だけ画面で補う
MCP で動かせるアプリでも、届かないボタンが残りますよね。国内の X 投稿（2026年8月23日）は、Unreal Engine で作った町を撮った例です。書き出し機能の MRQ が MCP に無く、computer-use で画面から操作して町の動画を書き出しています（投稿に付いた動画は10秒）。
ここがポイントなんです。公式の道具の順番も、MCP やコネクタが先で画面は最後でした。具体的にどうやったかというと…
Unreal Engine（Claude Code）：Movie Render Queue（MRQ）の書き出しだけを画面で操作

## 遅い・重い・止まる場面と、このPCでできなかった例

## そのまま使える頼み方の型（5項目）
依頼文に何をどこまで書けばいいか、迷いますよね。私の CapCut の依頼は「次だけCapCut立ち上げてやってみて」の1行でした。一方で Grok Bot の依頼文には、5つの決まりを書いています。具体的にどう書くかというと、次の5項目を埋めます。
アプリ名：「CapCut で」「Keynote で」と名指しする
素材の場所：ムービーフォルダの下など、アプリが読める場所を書く
やること：件数と対象を数字で書く
しないこと：購入・投稿・送信などを書く
終わったら見せるもの：書き出したファイルや、画面の写真
X の投稿には、依頼の最後に「Computer Useでお願い」と付けるという助言がありました（2026年8月17日）。数分で340件を調べた報告には、件数や対象を具体的に書くとよい、という助言も付いていました（2026年8月19日）。写真を1枚ずつ見せる作業はトークン（使用量の単位）を多く使い、会員登録やカード決済は断られるそうです。
正直に書くと、X では Computer Use は Codex の方が速くて正確だ、という比較が目立つんです。外出先からなら、Cowork の Dispatch でスマホから PC に作業を渡せます。ウォートン校の教授のニュースレター（2026年3月31日）には、PowerPoint のグラフ更新の例があります。ターミナルの Claude Code では、Dispatch は使えません。

## 第4章のまとめ　依頼文は5項目、まずアプリ名から
要するに、Computer Use は遅く、ファイルを選ぶ窓や画面ロックで止まる道具だということです。だからこそ依頼文には、アプリ名・素材の場所・しないことを先に書きます。

## おわりに　今日、Keynote か Numbers に1本頼む
CapCut のリールも Grok Bot の14件の表も、Claude Code が画面を見て押した結果です。止まる場面はあっても、手で繰り返していた作業は1つずつ渡せます。
今日やることは1つです。ターミナルなら /mcp で computer-use を Enable、デスクトップアプリなら設定でオンにします。続けて Keynote か Numbers を名指しし、作ってほしいスライドか表を1本頼んでください。
Claude Code の Computer Use なら、CapCut や Keynote も画面越しに動かせます。最初の1本は、アプリ名・やること・しないことの3行で書きます。
