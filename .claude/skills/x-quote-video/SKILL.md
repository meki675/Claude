# X記事の引用動画を作って下書きに保存する

1回の実行で作るのは**最大3本**。Claude in Chrome（ログイン済みのChrome）が必要。
Chromeの操作に入る前に、Claude in Chrome のスキルを読み込むこと。

## 1. 記事を探す（Chrome）
- `https://x.com/home` を開き、右上のアカウントが **@seiri_gakari** であることを確認する（違えば止めてユーザーに伝える）。
- 「おすすめ」タブをスクロールして、**記事（記事タブ）形式のポスト**で、AI（Claude・ChatGPT・Gemini・生成AI・AIエージェント・業務自動化など）がテーマのものを集める。
- 各候補のポストURLで次を実行し、`views=` が **10000以上** のものだけ残す。
  `python3 -I video/fetch_article.py <ポストURL> video/posts/<短い英語名>/`
- `video/posts/done.txt` に載っているURLは作成済みなので飛ばす。
- 自分の記事（@seiri_gakari 本人）は対象外にする。

## 2. 動画を作る
- `article.md` を全部読み、`cover.jpg` を目で見る。
- **デザインの様式**：`script.json` の `"style"` に `brutal / swiss / glass / crt / editorial` のどれかを書く（省略すると従来の見た目）。直近2本（`video/posts/*/script*.json` の `style`）と同じ様式は使わない。見比べ画像は `video/patterns/styles-compare.jpg`。様式は書体・線・角・影・背景の質感と専用の色を持つので、サムネがオレンジでも毎回オレンジにならない。
- **配色**：様式を使わないときだけ、サムネの背景色・文字色・差し色に近い配色を `video/lib/themes.js` から選ぶ。合うものがなければ新しく足す（明朝のサムネなら `orchard` のように見出しフォントも変える）。
- **演出アイデアを毎回ちがうサイトから借りる**：`node video/inspire.mjs /tmp/inspire` を実行し、保存された画像を見て、借りる見せ方を1つ決める（開けなかったサイトは Chrome で開く）。`script.json` に `"inspiration": {"site", "work", "idea"}` を書く。足りない動きは新しいシーンとして作る。
- **構成を毎回変える**：`video/references.md` を読み、直近3本（`video/posts/*/script.json` の `structure` と `reference`）と違う**構成の型**と**参考リポジトリ**を1つずつ選ぶ。
  - 参考リポジトリは Chrome で開き、デモやテンプレートから「見せ方」を1つ借りる（場面の順番、文字の出方、切り替えなど）。今の部品で足りなければ `lib/scenes.js` と `lib/style.css` に新しいシーンや動きを足す。
  - `script.json` に `"structure": "<型の名前>"` と `"reference": "<owner/repo>：借りたもの"` を書く。
- **台本**：`script.json` に書く。15〜20秒、5〜6場面にする。
  - 1場面目は大きな動きにする（`burst` / `stomp` / `shutter` / `ripple` / `orbit` のうち、直近と違うもの。借りた演出から新しく作ってもよい）。サムネの雰囲気に合えば `sparkles`（星）や `"shape": "leaf"`（葉っぱ）を使う。
  - `"transition"` は `["zoom", "flash", "slide", ...]` のように場面ごとに変える。`footer` は `出典：@<著者> のX記事` とする。
  - 最後は `cta` にして、`"image": "cover.jpg"` を付ける。
  - 中身は記事の**具体的に役立つ点・他より優れている点**（手順、数値、比較、そのまま使える指示文など）に絞る。記事にない事実や数字は足さない。
- **動きは数字で決める**（共有マニュアルの考え方）：「少し大きく」「ふわっと」ではなく、コマ番号・％・px で書く。テロップは `telop` シーンを使う（1文字2コマずらし・3〜4コマ目に124%の行き過ぎ・9コマ目で停止・帯は左から 58%→98%→100%・寄り 104.7%→108.1%）。緩急を強くしすぎない。
- **時刻は拍で決める**：`script.json` に `"bpm": 120` などを書き、場面の長さは `"beats"` で書く（120BPMなら1拍0.5秒）。切り替えがBGMの拍に乗る。
- **参考動画があるとき**：`python3 -I video/analyze_ref.py <URL か ファイル> /tmp/ref` で1秒30コマに分け、一覧（sheet.png）・コマごとの測定（measure.csv）・切り替わり（cuts.txt）を作り、数字を台本に写す。借りるのは尺・拍・コマ数・動き方・切り替えの種類・レイアウトの型だけ。色・書体・文言・映像・音は使わない。
- **コマで確かめる**：本番の前に `node video/frames.mjs <script.json> --scene <番号> --frames 0,1,3,4,7,9,27 --out /tmp/f.png` で決めたコマ番号を並べ、数字どおりか見る。ずれていたら「何コマ目の、どの文字が、どれだけ違うか」を書き出してから直す。
- **確認**：まず静止画を書き出す。
  `node video/render.mjs video/posts/<名前>/script.json --only-thumbs --thumbs /tmp/<名前>`
  画像を見て、文字の切れ・はみ出し・改行の崩れを直す。
- **書き出し**：`node video/make.mjs video/posts/<名前>/script.json --out video/posts/<名前>/<名前>-16x9.mp4` で BGM づくり・書き出し・重ねまで一度に行う（`"bpm"` `"mood"` を script.json に書く）。個別に行う場合は次のとおり。
  ```
  python3 video/bgm.py <秒数> /tmp/<名前>.wav --bpm 120〜136 --mood bright|dark
  node video/render.mjs video/posts/<名前>/script.json --out /tmp/<名前>-silent.mp4
  ffmpeg -y -i /tmp/<名前>-silent.mp4 -i /tmp/<名前>.wav -c:v copy -c:a aac -b:a 192k -shortest -movflags +faststart video/posts/<名前>/<名前>-16x9.mp4
  ```

## 3. 引用コメントを書く
- `video/posts/<名前>/quote-post.md` に3案を書き、案1を使う。
- **抽象的にしない**。「勉強になる」「すごい」などで終わらせず、記事の一番使える点を具体的に書く（何ができる／何分短くなる／どの設定をどう変える／どの指示文を使う、など）。
- **記事を読むメリットを必ず書く**。「この記事を読むと何が手に入るか」を具体的に1つ以上入れる（例：10個すべてにコピペできる依頼文／失敗した場面まで書いてあるので先につまずきが分かる／そのまま使える指示書2本）。動画の内容紹介だけで終わらせない。
- **感情を込める**。読んだときの驚き・共感・反省・「助かった」などの本音を一言入れ（例：「正直、読んで力抜けました…」「これはマジで刺さった」）、そのうえで具体的な中身を書く。絵文字は1〜2個まで。
- 案は3つとも型を変える（例：「これ自分の仕事だ」型／失敗も書いてある型／モヤモヤ解消型）。
- 140字以内（全角）を目安にする。最後は「〇秒でまとめました👇」のように動画へつなげる。
- 書き手は @seiri_gakari。他人の記事なので「記事にまとめています」ではなく「元記事が詳しいです」のように書く。

## 4. 下書きに保存する（Chrome）
- 元記事のポストを開き、リポスト → 「引用」を選ぶ。
- 引用コメント（案1）を入力し、動画ファイルを添付して「準備完了」まで待つ。
- **投稿ボタンは押さない**。作成画面を閉じ、「下書きを保存」を選ぶ。
- 下書き一覧（作成画面の「下書き」）に入ったことを確認する。引用ポストが下書きに残らない場合は、止めてユーザーに伝える（勝手に投稿しない）。

## 5. 記録する
- `video/posts/done.txt` に `日付<TAB>ポストURL<TAB>フォルダ名` を1行追記する。
- 動画・台本・quote-post.md・cover.jpg をコミットしてプッシュする。
- 最後に、作った本数・各記事のタイトル・使った引用コメントを短く報告する。
